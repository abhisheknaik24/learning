# Interview Preparation Documentation

When I ask for interview preparation content for one or more of these technologies, create or update a separate Markdown file in the workspace root for each requested technology:

- C# → `CSharp.md`
- .NET Core → `DotNetCore.md`
- Entity Framework → `EntityFramework.md`
- SQL → `SQL.md`
- JavaScript → `JavaScript.md`
- React.js → `ReactJS.md`
- Angular → `Angular.md`

Each file should contain clearly organized interview questions with accurate, direct answers. Group questions by topic and, where useful, by difficulty. Include concise code or SQL examples when they clarify an answer. Distinguish version-specific behavior when relevant, and do not invent details; verify uncertain or current framework-specific information before including it.

Organize every interview guide progressively from beginner to advanced: start with foundational concepts, then cover intermediate practical knowledge, and finish with advanced concepts, design trade-offs, and realistic scenarios. Do not skip foundational topics when adding advanced material. When I ask for a particular topic, level, or number of questions, follow that scope while preserving this progression where applicable. Otherwise, provide broad coverage across all three levels without padding the document with repetitive questions. Preserve and improve existing material when updating a file, and avoid changing files for technologies I did not request.

Use Markdown headings, readable code fences with language identifiers, and a table of contents when the document is long. Do not create one combined document unless I explicitly ask for it. For requests to set up this workflow or its instructions, do not generate the interview files unless I also ask for their content.
